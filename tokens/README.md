# Lime Glass - Tokens

Single source of truth for palette, spacing, radius, blur, opacity, shadow, typography, motion, glass, ambient.

**Schema v3 (2026-07-14):** the palette is **multi-variant** and authored in
**OKLCH** (perceptually uniform). Colors live only in `[variants.<name>]`
(`lime` = default, `indigo` = heritage); shared tokens (spacing/radius/blur/type/
motion/glass) are variant-agnostic. `[meta].default_variant` selects the active
variant. `codegen.py` derives byte-identical sRGB hex (for KDE/GTK/GRUB/Windows,
which cannot parse `oklch()`), Display-P3, and native `oklch()` CSS from the same
source values — so there is zero color drift across layers. It emits BOTH the
active-variant **default** file (e.g. `css-vars.css`) AND one **per-variant** file
each (`css-vars.lime.css`, `css-vars.indigo.css`, …). Sections:
`[radius.squircle]`, `[glass.grain]`, `[ambient]`, `[motion.roles]`.

## Files

Each artifact is written as the active-variant default (unsuffixed) plus one
suffixed file per variant (`.lime.<ext>` / `.indigo.<ext>`).

| File | Purpose |
|------|---------|
| `indigo-glass.tokens.toml` | Canonical token values (edit this) — palette in `[variants.<name>]` (OKLCH triples) |
| `codegen.py` | Reads tokens, emits per-layer artifacts (run this); includes dependency-free OKLCH↔sRGB↔P3 conversion |
| `out/css-vars.css` + `out/css-vars.{lime,indigo}.css` | CSS custom properties + `@supports` oklch() upgrade + P3 overlay (generated) |
| `out/scss-vars.scss` + `out/scss-vars.{lime,indigo}.scss` | Sass variables (generated) |
| `out/json-tokens.json` | JSON dump (all variants) + `_derived.palette` {hex,p3,oklch} for JS consumers (generated) |
| `out/kde-palette.colors` + `out/kde-palette.{lime,indigo}.colors` | KDE color scheme partial — derived RGB (generated) |
| `out/wt-scheme.json` + `out/wt-scheme.{lime,indigo}.json` | Windows Terminal scheme — derived hex (generated) |
| `out/density.css` | Compact-density CSS rules — variant-agnostic (generated) |
| `out/glass.css` + `out/glass.{lime,indigo}.css` | `.ig-glass` + grain texture + `.ig-squircle` + `.ig-ambient` orbs (generated) |

## Workflow

```bash
# Edit values
$EDITOR tokens/indigo-glass.tokens.toml

# Regenerate
python3 tokens/codegen.py

# Verify outputs in tokens/out/

# Commit both source + generated files
git add tokens/
git commit -m "tokens: bump lime accent to ..."

# CI check: fail if generated files are stale
python3 tokens/codegen.py --check
```

## Why TOML > JSON for source

- Comments (explain why each value)
- Trailing commas don't matter
- Hand-editable without quoting hell
- Python 3.11+ has `tomllib` built-in

## Why compact-density tokens

See [docs/DENSITY.md](../docs/DENSITY.md) for the rationale. Default OS chrome (Klassy/Material/Win Fluent) ships generous padding for new users + touch. Lime Glass tightens for power-users on 1440p+ desktops without crowding letters.

## Why visionOS-translucent (NOT Apple Liquid Glass refraction)

We use `backdrop-filter: blur()` with low-opacity accent tint, plus a static
fractal-noise **grain** layer on top (Glassmorphism 2.0 — `[glass.grain]`). No
refraction filter in the base glass. No specular highlights. Backdrop blur =
ambient context, never distracting.

See `[glass]` / `[glass.grain]` sections in `indigo-glass.tokens.toml`, emitted
to `out/glass.css` as `.ig-glass` and the standalone `.ig-grain` utility.

## OKLCH color authoring (schema v3)

The palette source of truth is `[variants.<name>]` — `[L, C, H]` triples per
variant (`lime` default, `indigo` heritage). codegen resolves
`[meta].default_variant` and derives everything else (the example below is the
default `lime` variant's `--ig-accent`):

```css
/* hex fallback (KDE/GTK/GRUB/Windows + old browsers) */
:root { --ig-accent: #A8E635; }

/* native oklch upgrade (all current browsers) */
@supports (color: oklch(0% 0 0)) {
  :root { --ig-accent: oklch(0.8523 0.2049 127.71); }
}

/* P3 wide-gamut overlay (more chroma on capable monitors) */
@media (color-gamut: p3) {
  :root { --ig-accent: color(display-p3 ...); }
}
```

All three round-trip to the **same** perceptual color; the hex values are
byte-identical to the OKLCH source (verified in codegen). Hover/active variants
are derived in CSS via relative color syntax
(`oklch(from var(--ig-accent) calc(l + 0.06) c h)`) so the single-accent rule holds.

## Squircle corners

`[radius.squircle]` → `out/glass.css` `.ig-squircle`. Progressive enhancement:
`corner-shape: superellipse(2)` on Chromium 139+, standard `border-radius`
fallback everywhere else.

## Ambient light orbs

`[ambient]` → `out/glass.css` `.ig-ambient`. Large, soft radial gradients behind
glass ("lit glass"). Single-accent hues only (indigo/violet at 3-6%).

## Accessibility

`prefers-reduced-transparency` -> blur disabled, opacity raised to 1.0.
`prefers-reduced-motion` -> durations zeroed.

Built into `out/css-vars.css` as `@media` queries.
